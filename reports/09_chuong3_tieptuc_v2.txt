3.4. Mô hình hóa hệ thống

3.4.1. Sơ đồ lớp

Các lớp cốt lõi trong hệ thống:

```
Lớp User (Người dùng):
- Thuộc tính: id, name, email, password, role, created_at, updated_at
- Phương thức: orders(), cartItems(), authenticate(), hasRole()

Lớp Product (Sản phẩm):
- Thuộc tính: id, name, slug, description, price, stock, category_id, specifications, images
- Phương thức: category(), orderItems(), inStock(), updateStock()

Lớp Category (Danh mục):
- Thuộc tính: id, name, slug, description, parent_id, is_active
- Phương thức: products(), parent(), children(), isActive()

Lớp Order (Đơn hàng):
- Thuộc tính: id, user_id, total, status, payment_method, payment_status
- Phương thức: user(), orderItems(), updateStatus(), calculateTotal()

Lớp OrderItem (Mục đơn hàng):
- Thuộc tính: id, order_id, product_id, quantity, price
- Phương thức: order(), product(), subtotal()

Lớp CartItem (Mục giỏ hàng):
- Thuộc tính: id, user_id, product_id, quantity
- Phương thức: user(), product(), subtotal()
```

3.4.2. Sơ đồ thành phần

Các thành phần kiến trúc hệ thống:

a) Lớp trình bày:
• Mẫu Blade: Render phía máy chủ
• Thành phần Alpine.js: Tương tác phía khách hàng
• Tailwind CSS: Khung styling
• Thiết kế phản hồi: Phương pháp mobile-first

b) Lớp ứng dụng:
• Controllers HTTP: Xử lý yêu cầu
• Form Requests: Xác thực đầu vào
• Middleware: Xác thực, CORS, giới hạn tốc độ
• Lớp dịch vụ: Đóng gói logic nghiệp vụ

c) Lớp miền:
• Models Eloquent: Biểu diễn dữ liệu
• Mẫu Repository: Trừu tượng hóa truy cập dữ liệu
• Hệ thống sự kiện: Xử lý thông báo tách rời
• Hàng đợi công việc: Xử lý nền

d) Lớp cơ sở hạ tầng:
• Cơ sở dữ liệu: MySQL với công cụ InnoDB
• Cache: Redis cho phiên và cache truy vấn
• Lưu trữ file: Local hoặc S3 cho hình ảnh
• Email: SMTP với xử lý hàng đợi

3.4.3. Sơ đồ triển khai

Kiến trúc môi trường sản xuất:

```
Internet → Cân bằng tải → Máy chủ Web (Nhiều instance)
                      → Máy chủ ứng dụng (Laravel)
                      → Máy chủ cơ sở dữ liệu (MySQL RDS)
                      → Máy chủ Cache (Redis ElastiCache)
                      → Lưu trữ file (S3)
                      → Dịch vụ Email (SES)
```

Tích hợp dịch vụ AWS:
• Elastic Beanstalk: Lưu trữ ứng dụng
• RDS MySQL: Cơ sở dữ liệu được quản lý
• ElastiCache Redis: Cache được quản lý
• S3: Lưu trữ đối tượng cho hình ảnh
• CloudFront: CDN cho tài sản tĩnh
• Route 53: Quản lý DNS
• Certificate Manager: Chứng chỉ SSL

3.5. Thiết kế cơ sở dữ liệu

3.5.1. Sơ đồ quan hệ thực thể (ERD)

Hệ thống PC Shop sử dụng 7 thực thể chính với các mối quan hệ như sau:

```
USERS (1) ←--→ (N) ORDERS
USERS (1) ←--→ (N) CART_ITEMS
CATEGORIES (1) ←--→ (N) PRODUCTS  
PRODUCTS (1) ←--→ (N) ORDER_ITEMS
PRODUCTS (1) ←--→ (N) CART_ITEMS
ORDERS (1) ←--→ (N) ORDER_ITEMS
ORDERS (1) ←--→ (N) PAYMENT_TRANSACTIONS
```

3.5.2. Thiết kế lược đồ cơ sở dữ liệu

a) Bảng Users (Người dùng):
```sql
CREATE TABLE users (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    email VARCHAR(255) UNIQUE NOT NULL,
    email_verified_at TIMESTAMP NULL,
    password VARCHAR(255) NOT NULL,
    role ENUM('admin', 'customer') DEFAULT 'customer',
    remember_token VARCHAR(100) NULL,
    created_at TIMESTAMP NULL,
    updated_at TIMESTAMP NULL,
    
    INDEX idx_users_email (email),
    INDEX idx_users_role (role)
);
```

b) Bảng Categories (Danh mục):
```sql
CREATE TABLE categories (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    slug VARCHAR(255) UNIQUE NOT NULL,
    description TEXT NULL,
    parent_id BIGINT UNSIGNED NULL,
    sort_order INT DEFAULT 0,
    is_active BOOLEAN DEFAULT TRUE,
    is_featured BOOLEAN DEFAULT FALSE,
    meta_title VARCHAR(255) NULL,
    meta_description TEXT NULL,
    meta_keywords VARCHAR(255) NULL,
    image VARCHAR(255) NULL,
    icon VARCHAR(255) NULL,
    color VARCHAR(7) NULL,
    created_at TIMESTAMP NULL,
    updated_at TIMESTAMP NULL,
    
    FOREIGN KEY (parent_id) REFERENCES categories(id) ON DELETE SET NULL,
    INDEX idx_categories_slug (slug),
    INDEX idx_categories_parent (parent_id),
    INDEX idx_categories_active (is_active)
);
```

c) Bảng Products (Sản phẩm):
```sql
CREATE TABLE products (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    category_id BIGINT UNSIGNED NOT NULL,
    name VARCHAR(255) NOT NULL,
    slug VARCHAR(255) UNIQUE NOT NULL,
    description TEXT NULL,
    price DECIMAL(10,2) NOT NULL,
    stock INT DEFAULT 0,
    image VARCHAR(255) NULL,
    images JSON NULL,
    specifications JSON NULL,
    is_featured BOOLEAN DEFAULT FALSE,
    views INT DEFAULT 0,
    created_at TIMESTAMP NULL,
    updated_at TIMESTAMP NULL,
    
    FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE CASCADE,
    INDEX idx_products_category (category_id),
    INDEX idx_products_slug (slug),
    INDEX idx_products_price (price),
    INDEX idx_products_featured (is_featured),
    FULLTEXT idx_products_search (name, description)
);
```

d) Bảng Orders (Đơn hàng):
```sql
CREATE TABLE orders (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT UNSIGNED NULL,
    total DECIMAL(10,2) NOT NULL,
    subtotal DECIMAL(10,2) NOT NULL,
    shipping_fee DECIMAL(10,2) DEFAULT 0,
    status ENUM('pending', 'processing', 'shipped', 'delivered', 'canceled') DEFAULT 'pending',
    customer_name VARCHAR(255) NOT NULL,
    customer_email VARCHAR(255) NOT NULL,
    customer_phone VARCHAR(20) NOT NULL,
    customer_address TEXT NOT NULL,
    payment_method ENUM('paypal', 'stripe', 'vnpay', 'cod') NOT NULL,
    payment_status ENUM('pending', 'completed', 'failed') DEFAULT 'pending',
    vnpay_txn_ref VARCHAR(255) NULL,
    notes TEXT NULL,
    created_at TIMESTAMP NULL,
    updated_at TIMESTAMP NULL,
    
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL,
    INDEX idx_orders_user (user_id),
    INDEX idx_orders_status (status),
    INDEX idx_orders_payment_status (payment_status),
    INDEX idx_orders_created (created_at)
);
```

e) Bảng Order_Items (Mục đơn hàng):
```sql
CREATE TABLE order_items (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    order_id BIGINT UNSIGNED NOT NULL,
    product_id BIGINT UNSIGNED NOT NULL,
    quantity INT NOT NULL,
    price DECIMAL(10,2) NOT NULL,
    created_at TIMESTAMP NULL,
    updated_at TIMESTAMP NULL,
    
    FOREIGN KEY (order_id) REFERENCES orders(id) ON DELETE CASCADE,
    FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE,
    INDEX idx_order_items_order (order_id),
    INDEX idx_order_items_product (product_id)
);
```

f) Bảng Cart_Items (Mục giỏ hàng):
```sql
CREATE TABLE cart_items (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    user_id BIGINT UNSIGNED NULL,
    product_id BIGINT UNSIGNED NOT NULL,
    quantity INT NOT NULL,
    created_at TIMESTAMP NULL,
    updated_at TIMESTAMP NULL,
    
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL,
    FOREIGN KEY (product_id) REFERENCES products(id) ON DELETE CASCADE,
    INDEX idx_cart_items_user (user_id),
    INDEX idx_cart_items_product (product_id),
    UNIQUE KEY unique_user_product (user_id, product_id)
);
```

g) Bảng Payment_Transactions (Giao dịch thanh toán):
```sql
CREATE TABLE payment_transactions (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    order_id BIGINT UNSIGNED NOT NULL,
    transaction_id VARCHAR(255) NOT NULL,
    payment_method ENUM('paypal', 'stripe', 'vnpay') NOT NULL,
    amount DECIMAL(10,2) NOT NULL,
    status ENUM('pending', 'completed', 'failed') NOT NULL,
    gateway_response JSON NULL,
    created_at TIMESTAMP NULL,
    updated_at TIMESTAMP NULL,
    
    FOREIGN KEY (order_id) REFERENCES orders(id) ON DELETE CASCADE,
    INDEX idx_transactions_order (order_id),
    INDEX idx_transactions_status (status),
    INDEX idx_transactions_method (payment_method)
);
```

3.5.3. Ràng buộc cơ sở dữ liệu và tối ưu hóa

a) Tính toàn vẹn tham chiếu:
• Ràng buộc khóa ngoại để duy trì tính nhất quán dữ liệu
• Xóa cascade cho các bản ghi phụ thuộc
• Giá trị null cho mối quan hệ tùy chọn

b) Xác thực dữ liệu:
• Ràng buộc ENUM cho các trường trạng thái
• Độ chính xác decimal cho dữ liệu tài chính
• Ràng buộc NOT NULL cho các trường bắt buộc
• Ràng buộc unique cho quy tắc nghiệp vụ

c) Tối ưu hóa hiệu suất:
• Khóa chính với AUTO_INCREMENT
• Chỉ mục phụ cho các cột được truy vấn thường xuyên
• Chỉ mục tổng hợp cho truy vấn nhiều cột
• Chỉ mục toàn văn cho chức năng tìm kiếm

d) Tối ưu hóa kiểu dữ liệu:
• BIGINT UNSIGNED cho khóa chính (hỗ trợ bộ dữ liệu lớn)
• VARCHAR với độ dài phù hợp
• Kiểu dữ liệu JSON cho dữ liệu có cấu trúc linh hoạt
• DECIMAL cho tính toán tài chính chính xác
• TIMESTAMP cho theo dõi ngày/giờ
